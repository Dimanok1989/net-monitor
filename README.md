# Мониторинг сетевых соединений

[English](docs/EN.md)

Утилита для Windows и Linux смотрит, какие программы открывают TCP-соединения, и пишет удалённые адреса в текстовые логи. На каждое приложение заводится отдельный файл на текущую дату.

## Запуск

### Windows

Дважды щёлкните `start-monitor.bat`.

Файл запросит права администратора. Подтвердите запрос: без них видны не все процессы, путь к exe часто пустой, а домены из системного DNS-кэша недоступны. Если запрос отклонить, мониторинг всё равно запустится, но только с правами текущего пользователя.

Окно остаётся открытым и дописывает новые адреса, пока вы не нажмёте Ctrl+C.

Повторный запуск в тот же день продолжит те же файлы и не продублирует уже записанные адреса. Второй экземпляр одновременно с первым не стартует.

### Linux

```sh
chmod +x net-monitor.sh
./net-monitor.sh
```

Скрипт запросит `sudo`, чтобы видеть все приложения и пути к ним. Если права root не дать, мониторинг продолжится с правами текущего пользователя. Остановка: Ctrl+C.

Интервал опроса, в секундах:

```sh
./net-monitor.sh --interval 5
```

## Куда пишутся логи

Каталог `logs` создаётся рядом со скриптом. Имя файла — имя приложения и дата:

```text
logs\chrome_2026-11-20.log
logs\dbeaver_2026-11-20.log
```

Для `svchost.exe` в имя добавляется служба из командной строки, например `svchost_Dnscache_2026-11-20.log`.

## Формат файла

```text
# dbeaver
# C:\Program Files\DBeaver\dbeaver.exe
192.168.1.10:5432
192.168.1.20:22    fileserver.local
```

Первая строка — имя приложения, вторая — путь к исполняемому файлу. Если путь недоступен, будет `# (путь недоступен)`. Дальше идёт список удалённых адресов: `IP:порт`, а через пробелы — домен, когда он известен. IPv6 записывается в скобках: `[2001:db8::1]:443`.

Один и тот же адрес за день хранится одной строкой. Если сначала записан только IP, домен дописывается в эту строку, как только он определится.

## Как это работает

Каждые 2 секунды скрипт читает таблицу TCP-соединений и сопоставляет их с процессами. Windows использует `netstat`, Linux — `ss`. В лог попадает удалённый адрес соединения, которое приложение само открыло. Слушающие порты и входящие подключения к ним не записываются. Петлевые адреса (`127.0.0.1`, `::1`) тоже пропускаются.

На Windows домен берётся из DNS-кэша, а если записи нет — из обратного DNS. На Linux имя запрашивает системный резолвер (`getent`). Имя из кэша ближе к тому, которое запрашивала программа. Обратное имя может принадлежать хостеру или CDN и появиться на строке на несколько секунд позже адреса.

## Параметры

Интервал опроса можно изменить, передав его в скрипт. Значение в секундах, от 1 до 3600:

```bat
start-monitor.bat -IntervalSeconds 5
```

Тот же параметр работает и при прямом запуске:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\net-monitor.ps1 -IntervalSeconds 5
```

Нужен Windows PowerShell 5.1, он уже есть в Windows 10 и 11.

На Linux интервал задаётся флагом `--interval`. Нужны `ss` (iproute2), `flock` (util-linux) и `getent`.

## Ограничения

- Пишутся только TCP-соединения. В таблице соединений нет адреса назначения UDP.
- Соединение короче интервала опроса может не попасть в лог.
- Домен не всегда совпадает с именем, которое вводили в программе: общий DNS-кэш и обратный DNS не привязаны к конкретному запросу приложения.
- Одновременно работает только одно окно мониторинга.
